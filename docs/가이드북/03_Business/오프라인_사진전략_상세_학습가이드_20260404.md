## 1️⃣ [문제 정의] 왜 오프라인 사진 전략인가?
크루즈 여행객은 망망대해나 해외 기항지에서 **데이터 연결이 끊기는 상황**을 수시로 겪습니다. 
- **문제점:** 기존 `<img>` 태그는 온라인 상태에서만 작동하며, 브라우저 캐시는 신뢰도가 낮아 오프라인 시 '엑스박스(Error)'가 발생합니다.
- **해결책:** 웹 표준 저장소인 **IndexedDB**를 활용하여 이미지를 '영구적'으로 기기에 저장하고, 네트워크가 없어도 즉시 꺼내 쓰는 **'로컬 우선(Local-First)'** 구조를 채택합니다.

---

## 2️⃣ [기초 설계] IndexedDB 이미지 저장소 구축
이미지 파일(`Blob`)을 데이터베이스에 저장하기 위해 `offlineStorage.ts`를 고도화했습니다.

### 📝 핵심 코드 분석 (`client/src/lib/offlineStorage.ts`)
```typescript
// 이미지 전용 객체 저장소(Object Store) 정의
const store = db.createObjectStore('landmark-images', { keyPath: 'url' });
store.createIndex('landmarkId', 'landmarkId', { unique: false });

// 이미지 저장 로직
async saveImage(url: string, blob: Blob, landmarkId?: string) {
    const db = await this.dbPromise;
    await db.put('landmark-images', {
        url,
        blob,
        landmarkId,
        timestamp: Date.now()
    });
}
```
- **학습 포인트:** `localStorage`는 용량 제한(5MB)과 문자열만 저장 가능하다는 단점이 있지만, `IndexedDB`는 기기 용량의 상당 부분을 사용할 수 있고 `Blob`(바이너리 데이터)을 직접 저장할 수 있어 이미지 캐싱에 최적입니다.

## 3️⃣ [핵심 로직] 지능형 훅과 컴포넌트 설계

### 🪝 `useOfflineImage.ts` (비즈니스 로직)
네트워크 상태와 DB 사이의 '교통정리'를 담당합니다.
1. **온라인 시:** 원본 URL 표시 + 백그라운드에서 `fetch` 후 DB에 저장.
2. **오프라인 시:** DB에서 `Blob`을 꺼내 `URL.createObjectURL(blob)`로 변환하여 브라우저에 임시 전달.

### 🧱 `OfflineImg.tsx` (UI 컴포넌트)
단순한 이미지가 아닌, 사용자에게 **성능적 우위**를 제공하는 프리미엄 UI입니다.
- `framer-motion`의 `layoutId`와 `initial/animate`를 결합하여 부드러운 전환 구현.
- `src` 속성에 `useOfflineImage` 훅을 내장하여 개발자가 사용하기 매우 편리한 형태입니다.

## 4️⃣ [시스템 통합] Service Worker와의 협업
브라우저 계층(IndexedDB)뿐만 아니라, 네트워크 계층(Service Worker)에서도 캐싱을 이중으로 지원합니다.

### ⚙️ `vite.config.ts` 설정
```typescript
runtimeCaching: [
  {
    urlPattern: /^https:\/\/images\.unsplash\.com\/.*/i,
    handler: 'CacheFirst', // 먼저 캐시 확인, 없으면 네트워크
    options: {
      cacheName: 'landmark-images-cache',
      expiration: { maxEntries: 100, maxAgeSeconds: 30 * 24 * 60 * 60 } // 30일 보존
    }
  }
]
```
- **학습 포인트:** 이중 캐싱(SW + IndexedDB)을 통해 첫 로딩 속도는 비약적으로 빨라지고, 오프라인 시의 신뢰도는 100%에 수렴하게 됩니다.

## 5️⃣ [데이터 혁신] 고화질 사진 자동화 스크립트 작성
수백 개의 데이터를 손으로 바꾸는 것은 비효율적입니다. `tsx` 스크립트로 자동화했습니다.

### 🤖 `update-landmark-photos.ts` (V2)
- **과제:** "모든 명소가 서로 다른 사진을 가져야 한다."
- **해결:** 명소의 고유 `id`를 해싱(Hashing)하여 50개의 프리미엄 사진 풀(Pool)에서 무작위로 배정하되, 매번 실행해도 동일한 명소에는 동일한 사진이 배치되도록 **결정론적(Deterministic) 알고리즘**을 사용했습니다.

---

## 6️⃣ [최종 검수] 성능 최적화와 린트(Lint) 해결
개발 과정에서 만난 난관과 해결책입니다.
- **린트 오류:** `src`가 `undefined`일 때 `fetch`나 `IndexedDB` 요청이 발생하는 타입 불일치 문제.
- **해결:** `loadAndCache` 함수 내부에 **Early Return** 타입 가드(`if (!src) return;`)를 추가하여 안정성을 확보했습니다.
