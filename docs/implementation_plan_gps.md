# 🛰️ GPS-랜드마크 연동 및 자동 안내 고도화 계획서

안녕하세요, 학생 여러분! 오늘은 우리 앱의 핵심 기능인 **GPS 기반 자동 오디오 가이드**를 완벽하게 연동하는 계획을 세워보겠습니다. 현재는 도시가 바뀔 때만 환영 메시지가 나오는데, 이제는 랜드마크 근처에만 가도 자동으로 설명이 흘러나오도록 만들어 볼 거예요.

## 🎯 목표
1. **도시 감지 확장**: 현재 하드코딩된 3개 도시(로마, 치비타베키아, 세부)를 DB의 모든 도시로 확장합니다.
2. **랜드마크 근접 감지**: 사용자가 랜드마크의 설정된 반경(Radius, 기본 50m) 안에 진입하면 이를 실시간으로 감지합니다.
3. **자동 오디오 트리거**: 진입 시 자동으로 오디오 가이드를 재생하고, 해당 장소를 '방문 완료'로 표시합니다.

## 🛠️ 주요 변경 사항

### 1. [Server Park] `client/src/lib/locationService.ts`
- **[MODIFY]** `CITY_HUBS`를 DB 데이터와 동기화하거나, 더 많은 주요 도시를 추가합니다. (도쿄, 파리, 바르셀로나 등)
- **[NEW]** `checkProximity(userPos, landmarks)` 유틸리티 함수를 추가하여 현재 위치에서 가장 가까운 미방문 랜드마크를 찾는 로직을 구현합니다.

### 2. [Server Park] `client/src/pages/Home.tsx`
- **[MODIFY]** `useEffect`를 강화하여 사용자의 위치(`position`)가 변할 때마다 주변 랜드마크와의 거리를 계산합니다.
- **[LOGIC]**
    - `distance <= landmark.radius` 판정 시:
        - `audioService.playAuto()`를 호출하여 나레이션 시작.
        - `markVisited(landmark.id)`를 호출하여 방문 기록 저장.
        - `UnifiedFloatingCard`를 해당 랜드마크로 자동 포커싱.

### 3. [Debug Doctor] GPS 시뮬레이션 테스트
- **[TEST]** 브라우저 'Sensors' 도구를 사용하여 가상의 위경도를 입력하고, 랜드마크 반경 진입 시 오디오가 끊김 없이 나오는지 확인합니다.
- **[DEBUG]** 이동 속도에 따른 감지 지연(Latency)을 최소화하기 위해 `useEffect`의 실행 빈도와 쾌적함을 조율합니다.

- **중복 재생 방지**: 이미 방문한 곳(isVisited)이나 이미 재생 중인 경우 중복 호출되지 않는가?
