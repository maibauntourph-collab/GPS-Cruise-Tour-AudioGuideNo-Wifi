# 화면 최소화(Minimize) 버그 분석 및 솔루션

작성일: 2026-04-04

---

## 1. 증상

UnifiedFloatingCard 헤더의 **↙ (Minimize2) 버튼** 클릭 시 카드가 최소화되지 않음.
- 버튼 클릭은 인식됨
- `onToggleMinimized` 함수도 정상 호출됨
- 그러나 카드 위치에 아무 변화 없음

---

## 2. 발견된 원인 (3가지)

### ① 핵심 원인 — `isCardVisible` 조건이 카드를 즉시 unmount

**파일:** `client/src/pages/Home.tsx`

```tsx
// 기존 (버그)
const isCardVisible = appMode !== 'map' || isSimulationMode;
```

**문제 흐름:**
1. 유저가 minimize 버튼 클릭
2. `setIsCardMinimized(true)` 호출
3. `transitionTo('map')` 호출 → `appMode = 'map'`
4. `isCardVisible = ('map' !== 'map') || false = false`
5. `{isCardVisible && createPortal(...)}` 조건 → **카드가 DOM에서 사라짐**
6. 최소화 애니메이션을 보여줄 카드 자체가 없어짐

**수정:**
```tsx
// 수정 후
const isCardVisible = appMode !== 'map' || isSimulationMode || isCardMinimized;
// isCardMinimized가 true이면 appMode 상관없이 카드 DOM 유지
```

---

### ② GPS proximity detection이 minimize 상태를 즉시 리셋

**파일:** `client/src/pages/Home.tsx` (proximity useEffect)

```tsx
// 기존 (버그)
useEffect(() => {
  ...
  if (manualClosedLandmarkRef.current !== landmark.id) {
    setSelectedLandmark(landmark);
    setIsCardMinimized(false);  // ← GPS가 근처 랜드마크 감지할 때마다 false로 덮어씌움!
  }
}, [effectivePosition, landmarks, audioEnabled, spokenLandmarks, selectedLanguage, offlineMode]);
//  ↑ isCardMinimized가 dependency에 없음 → stale closure!
```

**문제:** GPS 위치가 조금이라도 변하면 effect 재실행 → stale closure로 `isCardMinimized=false`라고 잘못 인식 → `setIsCardMinimized(false)` 호출 → minimize 상태 즉시 초기화.

**수정:**
```tsx
// 수정 후
if (manualClosedLandmarkRef.current !== landmark.id) {
  setSelectedLandmark(landmark);
  if (!isCardMinimized) {          // ← 이미 최소화 중이면 건드리지 않음
    setIsCardMinimized(false);
  }
}
}, [..., isCardMinimized]);        // ← dependency에 추가
```

---

### ③ `onToggleMinimized`에서 불필요한 `transitionTo('map')` 호출

**파일:** `client/src/pages/Home.tsx`

```tsx
// 기존 (버그)
onToggleMinimized={() => {
  setIsCardMinimized(!isCardMinimized);
  if (appMode === 'list') {
    transitionTo('map');   // ← appMode를 'map'으로 바꿔 isCardVisible=false 유발!
  }
}}
```

**수정:**
```tsx
// 수정 후 — 단순하게 toggle만
onToggleMinimized={() => {
  setIsCardMinimized(prev => !prev);
}}
```

## 3. 원래 CSS 방식의 추가 문제

기존 코드는 Tailwind 클래스로 minimize를 처리:
```tsx
// 기존
className={`... ${isCardMinimized ? 'translate-y-[calc(100%-60px)]' : 'translate-y-0'}`}
```

**문제:** `calc(100%-60px)` — 연산자 앞뒤 공백 없음 → CSS 표준 위반 → 브라우저에서 무효 처리.

**수정:** inline style로 전환
```tsx
style={{
  transform: isCardMinimized
    ? 'translateY(calc(100% - 60px))'   // ← 공백 포함, 정상 CSS
    : `translateY(${-dragOffset.y}px)`,
  transition: 'transform 0.4s cubic-bezier(0.4,0,0.2,1)',
}}
```

---

## 4. createPortal 적용 (사전 수정)

부모 컴포넌트의 `overflow-hidden` 속성으로 인해 카드가 잘리는 문제 해결.

```tsx
// Home.tsx
{isCardVisible && createPortal(
  <UnifiedFloatingCard ... />,
  document.body   // ← overflow 제약 없는 body에 직접 렌더링
)}
```

## 6. 동작 흐름 (수정 후)

```
유저가 ↙ 버튼 클릭
  ↓
setIsCardMinimized(true)
  ↓
isCardVisible = appMode !== 'map' || isSimulationMode || isCardMinimized
             = false || false || true = true  ← 카드 DOM 유지!
  ↓
transform: translateY(calc(100% - 60px))  ← 카드가 아래로 슬라이드
  ↓
헤더 60px만 화면 하단에 노출
  ↓
유저가 ROUTE FAB 버튼 클릭
  ↓
setIsCardMinimized(false) + transitionTo('list')  ← 카드 복원
```

---

## 7. "기존에 잘됐던" 이유

특정 조건(GPS 비활성화 또는 랜드마크 반경 밖)에서는 proximity detection이 실행되지 않아 ②번 문제가 발생하지 않았음. 그 상황에서만 일시적으로 작동하는 것처럼 보였던 것.
