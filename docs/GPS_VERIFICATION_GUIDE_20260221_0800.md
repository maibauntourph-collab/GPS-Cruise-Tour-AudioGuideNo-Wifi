# 🛰️ GPS-랜드마크 연동 정밀 검토 가이드 (2026-02-21)

교수님이 학생에게 설명하듯, GPS 연동 정합성을 완벽히 맞추기 위한 최강의 에이전트 연합과 전략을 안내해 드립니다.

## 1. 추천 에이전트 및 연합 (Agent & Skills)

| 에이전트 | 역할 | 핵심 스킬 |
| :--- | :--- | :--- |
| **도다리 (Dodari)** | **총괄 지휘** | GPS 감지부터 도시 랜딩까지의 전체 아키텍처 흐름(Workflow) 검토 및 제어 |
| **서버 팍 (Server Park)** | **로직 최적화** | `locationService.ts`의 위경도 판정 알고리즘 및 랜드마크 반경(Radius) 정밀도 강화 |
| **디버그 닥터 (Bug Doctor)** | **정밀 디버깅** | GPS 시뮬레이션 시의 런타임 로그 분석 및 위치 동기화 지연(Latency) 문제 해결 |

## 2. 추천 명령 프롬프트 (Antigravity용)

Antigravity 창에 아래 프롬프트들을 순차적으로 입력하여 작업을 진행하세요.

### [Phase A: 아키텍처 검토 - 도다리 수행]
> "모든 랜드마크의 위경도(Lat/Lng) 데이터와 `locationService.ts`의 실시간 위치 매핑 로직을 검토해줘. 특히 사용자가 설정한 반경(Radius) 안에 들어왔을 때 도시 랜딩 페이지가 정확한 시퀀스로 트리거되는지 확인하고 개선안을 제시해줘."

### [Phase B: 로직 정밀화 - 서버 팍 수행]
> "현재 GPS 감도가 낮을 때(Low Accuracy)의 예외 처리 로직을 강화하고, 랜드마크 진입 판정 시 부하를 줄이기 위한 계산 최적화를 진행해줘. `shared/schema.ts`의 좌표 포맷이 정확한지도 다시 확인해줘."

### [Phase C: 전수 검증 - 디버그 닥터 수행]
> "브라우저 F12 Sensors를 사용하여 여러 도시(도쿄, 싱가포르 등)의 좌표로 가상 이동했을 때, 콘솔에 'Landmark Detected' 로그가 실시간으로 찍히는지 전수 테스트하고 지연이 발생하면 코드를 수정해줘."

## 3. 활용 가능한 MCP 도구

1.  **sequential-thinking**: GPS 연동은 위치-감지-전환-데이터로드의 복잡한 단계를 거칩니다. 이 도구로 각 단계의 논리적 결함을 파악하세요.
2.  **TestSprite**: GPS 좌표 입력값에 따른 유닛 테스트 및 프론트엔드 통합 테스트를 자동화하여 '유령 진입' 등의 버그를 잡습니다.
