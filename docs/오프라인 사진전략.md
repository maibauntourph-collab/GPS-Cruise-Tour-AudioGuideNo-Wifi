# 오프라인 사진 전략

작성일: 2026-04-04

---

## 배경 및 목표

프로젝트명 "GPS-Cruise-Tour-AudioGuide-No-Wifi"의 핵심 기능인 오프라인 모드에서
도시 및 랜드마크 사진을 정상적으로 표시하기 위한 전략을 수립하고 구현한다.

- 국가 랜딩 페이지 사진(heroImage)은 기존 유지 (변경 없음)
- 도시 사진 및 랜드마크 사진만 오프라인 캐싱 적용
- 30일 주기 자동 갱신

---

## 논의 과정

### 1단계: 사진 소스 검토 (Viator API)

- 기존 `server/scripts/update-viator-photos.ts` 스크립트 존재
- Viator API → 이미지 URL 추출 → DB `photos` 컬럼에 URL 배열로 저장
- **저장 방식: URL만 저장 (JPG 파일 아님)**

```
Viator API → 이미지 URL 추출 → DB photos[] 컬럼 저장
```

### 2단계: 30일 주기 리프레시 방안 검토

| 방식 | 판단 |
|------|------|
| URL 리프레시 (photoReference 재발급) | ✅ 권장 - Google ToS 준수 |
| 이미지 직접 다운로드 후 재호스팅 | ⚠️ Google ToS 위반 가능성 |
| 사용자 접근 시 On-demand 리프레시 | ✅ 권장 - 앱 시작 시 만료 체크 |

### 3단계: 오프라인 이미지 전략 수립

**현재 문제점:**
- `useOfflineDownload.ts`에서 `fetch(url, {mode:'no-cors'})` 사용
- `no-cors`는 opaque response → 실제로 오프라인에서 이미지 깨짐

**선택한 방법:**

1. **Service Worker Cache** — 유저가 온라인에서 본 이미지 자동 캐시 (코드 최소)
2. **IndexedDB Blob 저장** — 도시 다운로드 시 이미지 실제 파일로 저장 (완전 오프라인)
3. **30일 갱신** — `isImageStale()` 체크 후 온라인 복귀 시 백그라운드 자동 재다운

## 구현 사항

### 신규 생성 파일 (2개)

#### `client/src/hooks/useOfflineImage.ts`
- 온라인: 원본 URL 사용 + 백그라운드에서 Blob → IndexedDB 저장 (30일 갱신)
- 오프라인: IndexedDB에서 Blob 로드 → `URL.createObjectURL()` 반환

#### `client/src/components/OfflineImg.tsx`
- `<img>` 드롭인 교체 컴포넌트
- `useOfflineImage` 훅 내장
- 사용법: `<OfflineImg src={url} alt="..." className="..." />`

---

### 수정 파일 (6개)

#### `vite.config.ts`
- 기존 Unsplash만 캐시 → Google / Viator / Wikipedia / Unsplash 통합
- 캐시명: `landmark-images`, 최대 1000장, 30일 유지
- 추가된 URL 패턴:
  - `lh[0-9].googleusercontent.com`
  - `maps.googleapis.com/maps/api/place/photo`
  - `upload.wikimedia.org`
  - `*.viator.com/*.{jpg,jpeg,webp,png}`

#### `client/src/lib/offlineStorage.ts`
- DB 버전: v3 → v4
- `imageFiles` store 신규 추가 (keyPath: `url`)
- 상수: `IMAGE_REFRESH_DAYS = 30`
- 추가 메서드:
  - `saveImage(url, blob, landmarkId?)` — Blob 저장
  - `getImage(url)` — 캐시 조회
  - `getImageObjectURL(url)` — `blob:` URL 반환
  - `isImageStale(url)` — 30일 경과 여부 체크
  - `deleteImagesByLandmark(landmarkId)` — 랜드마크별 삭제
  - `getImageStorageStats()` — 저장 통계
  - `clearAllImages()` — 전체 삭제
- `clearAll()`에 `imageFiles` 포함

#### `client/src/hooks/useOfflineDownload.ts`
- 기존 (broken): `fetch(url, {mode:'no-cors', cache:'force-cache'})`
- 변경 (실제 저장):
  - `isImageStale(url)` 체크
  - 만료된 경우에만 `fetch(url)` → `.blob()` → `saveImage()` 저장
  - 배치 3개씩 병렬 처리 (서버 부하 감소)

#### `client/src/components/PhotoGallery.tsx`
- 썸네일 `<img>` → `<OfflineImg>` 교체
- 풀스크린 `<motion.img>` → `<OfflineMotionImg>` 교체
  (motion props 유지를 위해 `useOfflineImage` 직접 사용하는 내부 컴포넌트)

#### `client/src/components/LandmarkDetailDialog.tsx`
- 미리보기 `<img src={landmark.photos[0]}>` → `<OfflineImg>` 교체

#### `client/src/components/UnifiedFloatingCard.tsx`
- 리스트 썸네일 `<img src={landmark.photos[0]}>` → `<OfflineImg>` 교체

## 동작 흐름

```
📶 온라인
  └─ 원본 URL 표시
  └─ 백그라운드: isImageStale() 체크
      └─ 30일 경과 → fetch → Blob → IndexedDB 저장

✈️ 오프라인
  └─ IndexedDB에서 Blob 로드
  └─ URL.createObjectURL() → <img src> 에 전달
  └─ 캐시 없으면 원본 URL 시도 (실패 가능)

🔄 도시 다운로드 버튼 클릭 시
  └─ 랜드마크 목록 다운로드
  └─ photos[] URL 배열 수집
  └─ 배치(3개씩) → fetch → Blob → IndexedDB 일괄 저장

🗑️ 용량 관리
  └─ clearAllImages() — 전체 삭제
  └─ deleteImagesByLandmark() — 도시 삭제 시 연동 가능
```

## 용량 예측

| 항목 | 용량 |
|------|------|
| 이미지 1장 (압축) | ~150KB |
| 랜드마크 사진 5장 | ~750KB |
| 도시 50개 랜드마크 | ~37MB |
| 도시 3개 | ~110MB |

## 향후 고려사항

- 도시 삭제 시 `deleteImagesByLandmark()` 자동 연동
- 설정 화면에서 이미지 캐시 용량 표시 (`getImageStorageStats()` 활용)
- WebP 압축 패키지 서버 제공으로 용량 절감 가능 (도시 1개 → 10MB 이하 목표)
- Google Photos Open API 정식 연동 검토 (v3 계획)
